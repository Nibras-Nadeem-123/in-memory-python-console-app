# Implementation Plan: Spec-Driven Todo System

**Branch**: `001-todo-system` | **Date**: 2025-12-28 | **Spec**: `specs/todo-system/spec.md`

## Summary

Build a Spec-Driven Todo application that accepts natural language commands for managing tasks in memory. The system interprets user intent, maintains an in-memory task list with history tracking, and provides clear feedback. Core workflow: user input → intent parsing → execution → output, with full undo capability.

**Technical Approach**:
- Modular architecture with 5 focused modules: input_parser, task_model, task_store, executor, cli
- Pure Python 3.9+ with zero external dependencies for core functionality
- In-memory state with deterministic transitions and operation history
- Title-based task referencing with fuzzy matching for natural UX

## Technical Context

**Language/Version**: Python 3.9+ (type hints, dataclasses, datetime)
**Primary Dependencies**: None (standard library only for core)
**Storage**: In-memory (dict-based), optional JSON export/import
**Testing**: pytest (unit + integration tests)
**Target Platform**: CLI (terminal, any OS with Python 3.9+)
**Project Type**: Single CLI application
**Performance Goals**: <100ms command response, <1s startup, <50MB memory
**Constraints**: No eval/exec, no external DB, safe deterministic execution
**Scale/Scope**: Up to 10,000 tasks, single-user session

## Module Breakdown

### 1. `task_model.py` - Data Entities

```python
# Task: Core data structure
@dataclass
class Task:
    id: int                      # Internal, never reused
    title: str                   # Task description
    status: str                  # "pending" | "completed"
    due_date: Optional[str]      # Natural language date
    created_at: datetime         # Timestamp

# Intent: Parsed user command
@dataclass
class Intent:
    action: str                  # add | list | update | complete | delete | undo | help | exit
    target: Optional[str]        # Title substring or ID reference
    new_title: Optional[str]     # For add/update
    due_date: Optional[str]      # For add/update

# Operation: For undo support
@dataclass
class Operation:
    action: str
    task_id: Optional[int]
    before_state: Optional[Task]  # None for add
    timestamp: datetime
```

**Responsibilities**:
- Define data structures with type hints
- Provide validation (e.g., status must be valid enum)
- No business logic, pure data containers

### 2. `task_store.py` - State Management

```python
class TaskStore:
    def __init__(self):
        self._tasks: dict[int, Task]  # id → Task
        self._next_id: int = 1
        self._history: list[Operation] = []

    # Core operations
    def add_task(self, title: str, due_date: Optional[str]) -> Task:
        """Create new task with incrementing ID"""

    def list_tasks(self) -> list[Task]:
        """Return all tasks ordered by ID"""

    def find_task(self, reference: str) -> Optional[Task]:
        """Match by title substring or ID, raise on ambiguous"""

    def update_task(self, task_id: int, title: Optional[str], due_date: Optional[str]) -> Task:
        """Modify task, record operation for undo"""

    def complete_task(self, task_id: int) -> Task:
        """Set status to completed, record for undo"""

    def delete_task(self, task_id: int) -> Task:
        """Remove task, record for undo"""

    def undo(self) -> Optional[Operation]:
        """Reverse last operation, return undone operation"""

    def get_history(self) -> list[Operation]:
        """Return operation history for inspection"""
```

**Responsibilities**:
- Maintain in-memory task dictionary
- Generate unique IDs (1-based, never reused)
- Record all operations for undo
- Provide deterministic state access

### 3. `input_parser.py` - Intent Recognition

```python
# Action patterns (first match wins)
ACTION_PATTERNS = {
    "add": [
        r"add task (.+)",
        r"add (.+)",
        r"new task (.+)",
        r"create task (.+)",
    ],
    "list": [
        r"list tasks?",
        r"show tasks?",
        r"list$",
        r"show$",
    ],
    "update": [
        r"update (.+) to (.+)",
        r"change (.+) to (.+)",
        r"set due date for (.+) to (.+)",
    ],
    "complete": [
        r"complete (.+)",
        r"mark (.+) done",
        r"finish (.+)",
        r"done (.+)",
    ],
    "delete": [
        r"delete (.+)",
        r"remove (.+)",
        r"drop (.+)",
    ],
    "undo": [
        r"undo",
        r"undo last",
    ],
    "help": [
        r"help",
        r"show help",
    ],
    "exit": [
        r"exit",
        r"quit",
        r"bye",
    ],
}

class InputParser:
    def parse(self, raw_input: str) -> Intent | ParserError:
        """Convert natural language to Intent or error"""
```

**Responsibilities**:
- Match input against action patterns
- Extract parameters using regex groups
- Handle due date extraction (e.g., "by Friday", "tomorrow")
- Return structured Intent or descriptive error

**Parsing Strategy**:
1. Normalize input (strip, lowercase for command matching)
2. Match against ACTION_PATTERNS in order
3. Extract due date from title if present ("... by [date]")
4. Return Intent with parsed components
5. Raise specific error for unknown/ambiguous input

### 4. `executor.py` - Command Execution

```python
class Executor:
    def __init__(self, store: TaskStore, output: OutputHandler):
        self.store = store
        self.output = output

    def execute(self, intent: Intent) -> ExecutionResult:
        """Execute intent and return result"""
        match intent.action:
            case "add": return self._add(intent)
            case "list": return self._list(intent)
            case "update": return self._update(intent)
            case "complete": return self._complete(intent)
            case "delete": return self._delete(intent)
            case "undo": return self._undo(intent)
            case "help": return self._help(intent)
            case "exit": return self._exit(intent)

    def _add(self, intent: Intent) -> ExecutionResult:
        """Add new task from intent parameters"""
```

**Responsibilities**:
- Execute actions from parsed intents
- Handle errors gracefully with user-friendly messages
- Coordinate with TaskStore for state mutations
- Return results for output

**Error Handling Flow**:
```
Executor catches error
    → Categorize error type
    → Format user-friendly message
    → Return (success=False, message)
    → CLI prints message
```

### 5. `cli.py` - Main Application

```python
def main():
    store = TaskStore()
    parser = InputParser()
    executor = Executor(store, OutputHandler())
    cli = CLI(parser, executor)

    print_welcome()
    cli.run()

class CLI:
    def __init__(self, parser: InputParser, executor: Executor):
        self.parser = parser
        self.executor = executor

    def run(self):
        while True:
            try:
                raw = input("> ").strip()
                if not raw:
                    print("Please enter a command. Type 'help' for available commands.")
                    continue

                intent = self.parser.parse(raw)
                result = self.executor.execute(intent)
                print(result.message)

                if intent.action == "exit":
                    break
            except KeyboardInterrupt:
                print("\nGoodbye!")
                break
            except Exception as e:
                print(f"Error: {e}")
```

**Responsibilities**:
- REPL loop (read → parse → execute → print)
- Handle edge cases (empty input, Ctrl+C)
- Initialize and wire components
- Print output and prompts

## Error Handling Strategy

### Error Taxonomy Implementation

```python
class ParserError(Exception):
    """Base class for parsing errors"""
    def user_message(self) -> str:
        raise NotImplementedError

class AmbiguousInputError(ParserError):
    """Multiple interpretations of user intent"""
    def user_message(self) -> str:
        return "I didn't understand. Which task? Please specify the title or ID."

class UnknownCommandError(ParserError):
    """No action pattern matched"""
    def user_message(self) -> str:
        return "Unknown command. Type 'help' for available commands."

class TaskNotFoundError(Exception):
    """Referenced task doesn't exist"""
    def __init__(self, target: str):
        self.target = target

    def user_message(self) -> str:
        return f"Task '{self.target}' not found. Did you mean to create it?"

class AmbiguousTaskError(Exception):
    """Multiple tasks match reference"""
    def __init__(self, target: str, matches: list[str]):
        self.target = target
        self.matches = matches

    def user_message(self) -> str:
        matches_str = ", ".join(self.matches)
        return f"Multiple tasks match '{self.target}': {matches_str}. Please be more specific."
```

### Error Handling Flow

1. **Parser Layer**: Validate syntax, return descriptive ParserError
2. **Executor Layer**: Catch TaskStore errors, format user messages
3. **CLI Layer**: Catch exceptions, print friendly message, continue loop
4. **No Error Propagation**: All errors caught and converted to user messages

## Key Design Decisions

| Decision | Alternative Considered | Rationale |
|----------|----------------------|-----------|
| Title-based task reference | User-facing IDs | More natural UX ("complete buy milk" vs "complete 1") |
| Dictionary for task storage | List | O(1) lookups by ID, easy iteration for list |
| Append-only history | Mutable history | Enables undo without complex rollback logic |
| Regex-based pattern matching | LLM/AI parsing | Zero dependencies, deterministic, fast |
| Dataclass entities | NamedTuple/class | Type hints, immutability, easy serialization |
| Single store instance | Global state | Testable, explicit dependencies |
