# Implementation Plan: Spec-Driven Todo Console Application

**Branch**: `006-todo-console-app` | **Date**: 2025-12-31 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/006-todo-console-app/spec.md`

## Summary

Build a console-based todo application that parses natural language commands into structured specifications before executing operations. The system maintains in-memory task state and supports CRUD operations through intuitive CLI commands. Uses pattern-based parsing (regex + keywords) for deterministic behavior without external dependencies.

**Core Value**: Demonstrate spec-driven development where intent → specification → execution separation enables transparency, testability, and clear boundaries.

## Architecture

### System Overview

```
┌─────────────────────────────────────────────────────────────┐
│                      User (Terminal)                        │
└────────────────────────┬────────────────────────────────────┘
                         │ text commands (stdin)
                         ↓
┌─────────────────────────────────────────────────────────────┐
│                     CLI Layer (REPL)                        │
│  • Read input                                               │
│  • Display results                                          │
│  • Handle exit                                              │
└────────────────────────┬────────────────────────────────────┘
                         │ raw string
                         ↓
┌─────────────────────────────────────────────────────────────┐
│                   Parser Layer (Intent)                     │
│  • Normalize input                                          │
│  • Extract operation type                                   │
│  • Extract parameters                                       │
│  • Build Command object                                     │
└────────────────────────┬────────────────────────────────────┘
                         │ Command (structured)
                         ↓
┌─────────────────────────────────────────────────────────────┐
│                  Executor Layer (Action)                    │
│  • Validate command                                         │
│  • Route to operation handler                               │
│  • Interact with storage                                    │
│  • Build CommandResult                                      │
└────────────────────────┬────────────────────────────────────┘
                         │ read/write operations
                         ↓
┌─────────────────────────────────────────────────────────────┐
│                   Storage Layer (State)                     │
│  • Maintain task dictionary                                 │
│  • Assign IDs                                               │
│  • CRUD operations                                          │
│  • Filter/search                                            │
└─────────────────────────────────────────────────────────────┘
```

### Data Flow

**Successful Operation**:
```
User Input: "add task: write tests with priority high"
    ↓
[CLI] Captures text
    ↓
[Parser] Analyzes:
    - Operation: ADD
    - Title: "write tests"
    - Priority: HIGH
    ↓
Command(operation=ADD, params={"title": "write tests", "priority": HIGH})
    ↓
[Executor] Validates command
    ↓
[Executor] Creates Task object
    ↓
[Storage] Assigns ID=1, stores task
    ↓
CommandResult(success=True, message="Task #1 created: 'write tests' (priority: HIGH)")
    ↓
[CLI] Displays: "Task #1 created: 'write tests' (priority: HIGH)"
```

**Error Handling**:
```
User Input: "complete task 999" (non-existent)
    ↓
[CLI] Captures text
    ↓
[Parser] Produces Command(operation=COMPLETE, task_id=999)
    ↓
[Executor] Validates command
    ↓
[Storage] Lookup fails (task_id not found)
    ↓
CommandResult(success=False, message="Task #999 not found. Use 'list' to see all tasks.")
    ↓
[CLI] Displays error with red formatting
```

### 2. Parser Layer (`src/input_parser.py`)

**Purpose**: Transform text into structured commands

**Responsibilities**:
- Normalize input (lowercase, strip whitespace)
- Detect operation type (ADD, LIST, COMPLETE, etc.)
- Extract parameters using regex patterns
- Validate extracted components
- Build Command object
- Raise ParseError for invalid input

**Boundaries**:
- ✅ MAY: Parse text, extract patterns, build Command
- ❌ MAY NOT: Execute operations, access storage, modify state

**Key Functions**:
```python
class InputParser:
    def parse(self, text: str) -> Command:
        """Parse text into Command object"""

    def _detect_operation(self, text: str) -> OperationType:
        """Identify operation type from keywords"""

    def _extract_add_params(self, text: str) -> Dict[str, Any]:
        """Extract title and optional priority"""

    def _extract_task_id(self, text: str) -> int:
        """Extract numeric task ID from text"""

    def _extract_update_params(self, text: str) -> Dict[str, Any]:
        """Extract update fields (title/priority)"""
```

**Parsing Strategy**:
1. Normalize: `text.lower().strip()`
2. Match operation keywords: `["add", "create", "new"]` → ADD
3. Apply operation-specific regex patterns
4. Validate extracted components
5. Return Command or raise ParseError

**Dependencies**: Uses `task_model` for Command, OperationType, Priority enums

**Purpose**: Execute commands and manage business logic

**Responsibilities**:
- Validate Command objects

- Build CommandResult with success/error messages

**Boundaries**:
- ✅ MAY: Execute operations, validate data, access storage
- ❌ MAY NOT: Parse text, format output for display, manage CLI

**Key Functions**:
```python
class TodoExecutor:
    def __init__(self, store: TaskStore):
        self._store = store

    def execute(self, command: Command) -> CommandResult:
        """Execute command and return result"""

    def _handle_add(self, command: Command) -> CommandResult:
        """Create new task"""

    def _handle_list(self, command: Command) -> CommandResult:
        """List tasks (all, pending, or completed)"""

    def _handle_complete(self, command: Command) -> CommandResult:
        """Mark task as completed"""

    def _handle_delete(self, command: Command) -> CommandResult:
        """Remove task"""

    def _handle_update(self, command: Command) -> CommandResult:
        """Update task properties"""

    def _handle_search(self, command: Command) -> CommandResult:
        """Search tasks by keyword"""
```

**Operation Handlers**:
- Each handler follows pattern: validate → execute → build result
- All handlers return CommandResult (never raise exceptions to CLI)
- Business logic validation happens here (e.g., "task already completed")

### 4. Storage Layer (`src/task_store.py`)

**Purpose**: Manage in-memory task collection

**Responsibilities**:
- Maintain Dict[int, Task] mapping
- Assign unique auto-incrementing IDs
- Provide CRUD operations
- Support filtering by status
- Support searching by title keyword
- Maintain ID sequence invariants

**Boundaries**:
- ✅ MAY: Store tasks, assign IDs, filter/search
- ❌ MAY NOT: Create Task objects (done by executor), format output, handle commands

**Key Functions**:
```python
class TaskStore:
    def __init__(self):
        self._tasks: Dict[int, Task] = {}
        self._next_id: int = 1

    def add(self, task: Task) -> int:
        """Add task and return assigned ID"""

    def get(self, task_id: int) -> Optional[Task]:
        """Retrieve task by ID"""

    def get_all(self) -> List[Task]:
        """Return all tasks ordered by ID"""

    def update(self, task_id: int, task: Task) -> bool:
        """Replace task with given ID, return success"""

    def delete(self, task_id: int) -> bool:
        """Remove task, return success"""

    def filter_by_status(self, status: TaskStatus) -> List[Task]:
        """Return tasks matching status"""

    def search(self, query: str) -> List[Task]:
        """Return tasks with query in title (case-insensitive)"""

    def count(self) -> int:
        """Return total number of tasks"""
```

**Invariants**:
- IDs are never reused (even after deletion)
- `_next_id` always points to next available ID
- All returned lists are sorted by ID ascending

**Dependencies**: Uses `Task` and `TaskStatus` from `task_model`

## Execution Flow

### Startup Sequence

```python
1. main() called
2. Display welcome message
3. Create TaskStore()
4. Create InputParser()
5. Create TodoExecutor(store)
6. Enter REPL loop
```

### REPL Loop

```python
while True:
    # 1. Read input
    text = input("> ").strip()

    if not text:
        continue

    try:
        # 2. Parse input
        command = parser.parse(text)

        # 3. Handle exit
        if command.operation == OperationType.EXIT:
            print("Goodbye!")
            break

        # 4. Execute command
        result = executor.execute(command)

        # 5. Display result
        display_result(result)

    except ParseError as e:
        # Show parse error with suggestion
        print(f"Parse error: {e.message}")
        if e.suggestion:
            print(f"Try: {e.suggestion}")

    except KeyboardInterrupt:
        print("\nGoodbye!")
        break
```

### Operation Execution Flow

**ADD Operation**:
```
1. Parser extracts title and priority from text
2. Parser creates Command(ADD, params={"title": ..., "priority": ...})
3. Executor receives command
4. Executor creates Task object (status=PENDING, id=None, created_at=now)
5. Executor calls store.add(task) → gets assigned ID
6. Executor builds CommandResult(success=True, message="Task #X created...")
7. CLI displays success message
```

**LIST Operation**:
```
1. Parser detects "list" keyword
2. Parser checks for filter ("pending"/"completed"/none)
3. Parser creates Command(LIST, params={"filter": ...})
4. Executor receives command
5. Executor calls store.get_all() or store.filter_by_status(...)
6. Executor builds CommandResult(success=True, data=task_list)
7. CLI formats and displays task list
```

**COMPLETE Operation**:
```
1. Parser extracts task ID
2. Parser creates Command(COMPLETE, task_id=X)
3. Executor receives command
4. Executor calls store.get(task_id) → retrieves task
5. If not found → error result
6. If found → create new Task with status=COMPLETED
7. Executor calls store.update(task_id, updated_task)
8. Executor builds success result
9. CLI displays confirmation
```

## Boundaries Between Spec and Execution

### Spec Phase (Parser Layer)

**What happens**:
- Text → structured representation (Command)
- Intent extraction and parameter parsing
- Syntactic validation only

**What does NOT happen**:
- No state changes
- No business logic validation (e.g., checking if task exists)
- No task creation or modification

**Output**: `Command` object (pure data, no side effects)

---

### Execution Phase (Executor Layer)

**What happens**:
- Command → state changes + feedback
- Business logic validation (e.g., task exists, not already completed)
- Task creation and storage interaction
- Result formatting

**What does NOT happen**:
- No text parsing
- No user I/O
- No CLI formatting

**Output**: `CommandResult` object (describes outcome, no I/O)

---

### Boundary Enforcement

**Type Safety**:
```python
# Parser outputs Command (spec)
command: Command = parser.parse(text)

# Executor takes Command, outputs Result (execution)
result: CommandResult = executor.execute(command)
```

**No Direct Communication**:
- Parser never calls Executor
- Executor never calls Parser
- CLI mediates all communication

**Testability**:
```python
# Test parser independently
def test_parse_add_command():
    parser = InputParser()
    command = parser.parse("add task: write tests")
    assert command.operation == OperationType.ADD
    assert command.params["title"] == "write tests"

# Test executor independently
def test_execute_add_command():
    store = TaskStore()
    executor = TodoExecutor(store)
    command = Command(OperationType.ADD, None, {"title": "test", "priority": Priority.MEDIUM})
    result = executor.execute(command)
    assert result.success is True
    assert store.count() == 1
```

## Error Handling

### Error Categories

1. **Parse Errors** (User's responsibility):
   - Invalid command format
   - Unrecognized operation
   - Missing required parameters
   - **Action**: Show error + suggestion, continue REPL

2. **Validation Errors** (User's responsibility):
   - Task ID not found
   - Invalid priority value
   - Empty title
   - **Action**: Show error + guidance, continue REPL

3. **System Errors** (Developer's responsibility):
   - Unexpected exceptions
   - Data corruption
   - **Action**: Log error, show generic message, optionally exit

### Error Flow

```python
try:
    command = parser.parse(text)
except ParseError as e:
    # Handle parse error gracefully
    display_error(e.message, e.suggestion)
    continue  # Keep REPL running

try:
    result = executor.execute(command)
    if not result.success:
        # Business logic failure (validation error)
        display_error(result.message)
    else:
        display_success(result.message, result.data)
except Exception as e:
    # Unexpected system error
    log.error(f"Unexpected error: {e}")
    display_error("System error occurred. Please try again.")
```

### User-Friendly Error Messages

**Bad**:

## Risks and Mitigations

### Risk 1: Ambiguous Command Parsing
**Likelihood**: HIGH
**Impact**: MEDIUM (users frustrated by parse errors)
**Mitigation**:
- Define clear command patterns in quickstart.md
- Provide helpful suggestions on parse errors
- Support multiple phrasings for common operations
- Test with diverse input variations

### Risk 2: Scope Creep
**Likelihood**: MEDIUM
**Impact**: HIGH (delays delivery, violates constraints)
**Mitigation**:
- Strict adherence to spec.md requirements
- Explicit "Out of Scope" section in spec
- No persistence, no advanced features
- Focus on MVP (User Story 1) first

### Risk 3: Test Coverage Gap
**Likelihood**: LOW (if process followed)
**Impact**: HIGH (can't safely refactor or extend)
**Mitigation**:
- Write tests alongside implementation (TDD)
- Track coverage with pytest-cov
- Gate PRs on 80% coverage minimum
- Review edge cases explicitly
